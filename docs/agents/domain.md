# Domain docs

CRS has one shared domain context. Its service, server, and site packages are
model, API, and UI layers of the same course-request system.

Before exploring domain concepts, read the root `GLOSSARY.md` if it exists.
Before changing a decision, read relevant records in `docs/adr/` if present.
Use the glossary's established vocabulary in code, issues, tests, and proposals.
Surface any conflict with an existing ADR explicitly.

If these docs do not exist, proceed silently. The domain-modeling skill creates
them when terminology or decisions are resolved; setup does not create empty
glossaries or ADRs.
